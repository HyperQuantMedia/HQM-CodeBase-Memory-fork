## Versioning

Convention, already documented at `.github/workflows/release.yml:8`:

```
<upstream-version>-hqm-v<hqm-semver>     e.g. v0.9.0-hqm-v0.1.0
```

Upstream has released nothing past `v0.9.0`, so the upstream axis stays pinned and **our axis
moves**. This cycle carries a feature port, a security wave and new capability — a minor bump:

> **`v0.9.0-hqm-v0.2.0`**

| Change | Bump |
|---|---|
| Security-only, no behaviour change | patch — `hqm-v0.1.1` |
| Features, ported work, new surfaces | minor — `hqm-v0.2.0` |
| Upstream cuts a new release | rebase the left axis, **reset ours to `hqm-v0.1.0`** — the hqm number describes our delta on *this* base |

**Known and accepted:** semver parses `0.9.0-hqm-v0.1.0` as `0.9.0` with prerelease `hqm-v0.1.0`,
and prereleases sort *below* the plain release — so strict tooling reads our build as **older**
than upstream `v0.9.0`. Ordering among our own releases is correct. Nothing in our path compares
across the two (the pin is exact-sha; Phase 2 removes the update check). Recorded so it is not
rediscovered as a bug.

## Scope note — arbitrary paths, not just repos

Cartograph must accept **any path, up to a whole hard drive** — the owner's framing is "the coolest
galaxy-style file explorer". That is a different mode from "index a repo", and it breaks four
engine assumptions:

1. **`.cbmignore` does not apply.** Read from the **repo root only**, at discovery time. Point at
   `D:\` and there is no repo root and no `.gitignore` hierarchy to layer under — the ignore stack
   degrades to the hardcoded patterns. **This settles A3b's storage: rules live in Cartograph's
   config**, because the file-based mechanism has nowhere to live.
2. **Whitelisting is two controls, not one semantics choice.** Both required at drive scale:
   - **Folder rules prune the walk** — never descend. The only thing that makes a drive tractable.
   - **Filetype rules filter what is kept** — require descending into whatever was not pruned. This
     is where the parent-directory trap lives, and where we handle descent ourselves so "only these
     types" behaves as expected.
3. **The watcher will not run.** It polls `git status` + HEAD and **skips non-git projects
   entirely** — no fsnotify, no dirmtime. A drive index is a snapshot that silently never
   refreshes, and nothing says so.
4. **Every node budget is blown.** The size map hard-caps at 8,000; a drive is millions of files.
   **D11 stops being cosmetic** — the omission notice becomes the primary honest signal about what
   is and is not on screen.

**Upstream already has an open crash here:** DeusData **#1241**, *"memory runaway (12.8 GB+ RSS)
during index_repository on root paths triggers OOM crash"*. The folder-pruning control mitigates;
the underlying crash is theirs.

| | Item | Where |
|---|---|---|
| 1 | Add `.note.GNU-stack` + ELF-only `-Wl,-z,noexecstack`. Its absence made GNU ld assume the worst for the whole link — **every Linux binary we have shipped had `GNU_STACK RWE`** | `vendored/nomic/code_vectors_blob.S`, the only assembly in the build |

| 6 | Stop descending symlinks out of the project root; fix 512-byte buffers truncating into pointer arithmetic | `src/pipeline/pass_envscan.c` |
| 7 | Drop mimalloc's `__DATE__`/`__TIME__`; add `-Wdate-time`, `-Wl,--no-insert-timestamp`. Without this no two builds of identical source can share a hash | `vendored/mimalloc/src/options.c` + flags |

### 4a · Colour

### 4b · Node sizing modes

A **"size by"** control, shared across both views per the parity ruling, with two toggleable
measures:

1. **Load-bearing** — primarily the graph view. How much depends on this node.
2. **Byte size** — primarily the size map. Applies to **directories as well as files**.

**Feasible, and cheaper than it looks.** `in_degree` and `out_degree` already exist in the store
(`src/store/store.h:126-127`), alongside a `min_degree` filter and `sort_by: "degree"` — they are
simply **not in the UI payload** (`types.ts` has no degree field). For the graph view, degree is
derivable client-side from the edge list already present, so **v1 needs no server change**.

**Definition:** in-degree is the honest first proxy for load-bearing — how many things reference
this. **Out-degree measures fragility, not load-bearing, and must not be conflated.** Upgrade path
if in-degree proves blunt: the engine already computes **hotspots** via `get_architecture` and
**Louvain clusters**, both unused by the viewer.

Byte size is already computed (`sizeMap.ts`, `/api/file-sizes`, with directory sums). The work is
making it a **mode** rather than the size map's hardcoded assumption — which is what lets the graph
view use it too.

### 4c · State and filters

- **A3a** — per-project filter persistence. **Filters are not persisted at all today**; `cbm-view`
  holds only projection/camera/animation, and the fifteen *quoted-literal* `cbm-*` keys are global.
  Filters and folder visibility go per-project; theme, panel widths, sort orders and projection stay
  global.
  **Reuse the existing precedent rather than inventing one:** `GraphTab.tsx:58-71` already persists
  the node budget per project with a templated key — `cbm-node-budget:${project}`, `loadNodeBudget`
  / `saveNodeBudget`, clamped on read, try/catch guarded. Generalise that pair into
  `lib/panelState.ts`, which both tabs already share
- **A3b** — ignore-rule UI generating `.cbmignore`. Because the file is **machine-generated the
  whitelist trap disappears** — we emit `!*/` and the user never sees negation syntax.
  **Hard constraint:** an ignore rule **cannot shrink an existing graph**
  (`pipeline_incremental.c:125-166` preserves nodes for any stored file still on disk as
  `mode-skipped` — a fail-safe after the 2026-04-13 Skyline incident, where
  `packages/mcp/src/tools/` vanished from a live graph mid-session). The UI must say so and offer
  the rebuild

## Phase 5 — Ingest and scale

- **A1** — batch indexing. `index_repository` takes one **required** `repo_path`; this is a loop
  over an existing tool
- **A2** — cross-repo. **Rendering already exists** — `LinkedProject` with `offset {x,y,z}` and
  `linked_projects[]`, consumed by `GraphScene.tsx`. The gap is the **links**: `pass_cross_repo.c`
  matches only Routes, Channels and async topics (capped 4,096), so markdown corpora produce
  nothing.
  **A cross-repo link means `Source:`** — settled empirically, not by design.
  `workspace-boundaries.md` *requires* a `Source:` pointer to sibling material, so the rule
  generates the edge set by construction: **31 files in the Astra corpus already carry them.**
  And we discard them — `hqm-md-bridge.js` classifies out-of-root targets as their own `outside`
  state, buckets them, and has **no emission branch** for that bucket. No node, no edge, no
  broken-link report. Some `Source:` references are inline code rather than links, so `readLinks`
  never sees those at all.
  **Work:** emit `outside` as a `SOURCE` edge resolved against sibling projects; recognise the
  inline-code form. Precedent — `pass_cross_repo.c` already writes `CROSS_*` bidirectionally by
  opening sibling `.db` files. **This lands in `HQM-Astra`, not this repo.**
- **A16** — failure trail. **The data already exists**: `index_repository` returns
  `skipped: {files:[{path, reason, phase}], count, truncated}` and
  `excluded: {dirs, count, truncated}`, and Phase 1 adds coverage to `index_status`. **Zero UI
  surface.** A display job, not instrumentation
- **E · the ADR panel — hide it.** `manage_adr` stores one mutable free-text blob per project and
  the engine nudges agents to dump "architectural insights" into it: **cross-session agent memory
  wearing the name ADR** (no numbering, no status, no one-decision-per-file, fully mutable). It
  duplicates — worse — `waypoint.md`, `decisions/` and Astra's `decisions/`. Remove the button from
  the Projects tab. One line, reversible if the distiller work later wants a per-project notes
  field. *(Upstream knows: DeusData #507 asks for real markdown ADRs.)*
